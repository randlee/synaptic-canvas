# Eval reports

Published HTML reports from `claude plugin eval` runs, one folder per plugin:

    site/reports/evals/<plugin-name>/<date-time>-<eval-name>.html

`<date-time>` is `YYYYMMDD-HHMMSS` from the run; `<eval-name>` is the case name for a
single-case run, else the suite/fixture name. This directory is served via GitHub Pages
and is the long-term record with full history — reports are never overwritten, only
added.

How reports arrive:

- **test-packages harness runs** of `<pkg>-evals` fixtures write here directly
  (`<date-time>-<pkg>-evals.html` + JSON sidecar + artifacts folder).
- **Standalone-runner / official `claude plugin eval` runs** are swept from
  `packages/*/evals/results/` (gitignored) by:

```bash
python3 scripts/collect-eval-reports.py
```

The landing pages are **build artifacts, generated by CI** — gitignored, never
committed. `pages.yml` regenerates them from the committed report files at deploy time
(and `validation.yml` regenerates + validates them on every push/PR), so the deployed
site can never be stale:

- `evals.html` — one section per plugin, showing the **most recent report for each
  eval** with its run count
- `<plugin>/history.html` — that plugin's **entire history**, newest first
- `index.html` — redirect to `evals.html` (the Pages landing for this folder)
- `../../announcements/index.html` — the announcements index, same process
  (`scripts/generate-announcements-index.py`)

The collector regenerates the same pages locally for preview. Only the **report files**
need committing; they are never overwritten without `--force`. The whole site is gated
by `scripts/validate-site-html.py` (structure + internal links/anchors) before deploy.
